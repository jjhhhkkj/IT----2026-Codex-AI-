# IT爱学堂-极客-2026年Codex AI工程交付行动营
获课：aixuetang.xyz/25021/

交付体系的工程化构建——知识资产、质量门禁与FDE角色的制度设计
当Codex能够承担越来越多的编码执行工作，工程团队真正稀缺的资源变成了“定义问题、判断结果、控制过程，以及对最终交付负责”的能力。围绕这一能力构建可持续的交付体系，需要回答三个制度性问题。

知识沉淀是唯一不可替代的护城河。 模型会迭代，工具链会更新，工作流会重构，但团队在特定业务领域积累的领域模型、架构决策、最佳实践、已知陷阱和业务流程——这些知识不会因为模型换代而失效。OpenAI的实验中，AGENTS.md文件从第一天起就是由Codex生成的，它充当智能体在仓库中工作的“行为契约”。团队需要设计知识分层架构：项目级资产包括Spec、接口契约、验收清单和回归策略；团队级资产包括组件模板、规范、风险模式库和测试资产；部门级资产包括质量门禁、评测口径和历史缺陷知识。工作流只是管道，知识才是流过管道的活水。

从“看实现”到“核对契约+验证证据”。 AI Coding在真实研发流程中的核心矛盾已经从“能不能写”转向“能不能稳定交付”。需求理解与实现经常漂移，AI产出缺少一致性约束，质量与回归验证成本被放大。破局的技术路径是以PRD→上线SOP为骨架，用“Work Item最小交接包+单一事实源+门禁化流程”让人和Agent可自由接力。具体而言，需求阶段将自然语言转化为可版本化的Spec和契约输入；研发阶段以门禁化协作控制AI参与边界；Review与测试阶段从“看实现”转为“核对契约+验证证据”；上线后线上信号回收反哺规范、测试和资产库。这一闭环的目标是把“靠经验选回归”升级为“可解释、可复算”的变更验证。

FDE角色作为交付体系的制度性支点。 FDE（Forward Deployed Engineer）的复合能力恰好对应了AI交付中最稀缺的环节：需求拆解——把模糊的业务问题变成边界明确、可执行、可验收的任务；过程控制——设计验证机制和反馈回路，确保Agent产出在可控范围内；效果验证——对最终业务效果负责，而非仅对技术指标负责。FDE属于驻客户现场的工程交付岗，在客户现场完成从需求梳理、方案设计到部署上线的全流程，把AI能力接进业务流程，最终对业务效果负责。行动营将Codex工程化能力与FDE交付方法论并行训练，正是看到了这两个维度的互补性：Codex解决“怎么用AI高效实现”，FDE解决“怎么确保实现的东西真正有用且可靠”。
